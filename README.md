# 포인트 서비스 프로젝트


---

## 주요 기능

- **포인트 조회**
    - `GET /point/{id}`  
      사용자의 현재 포인트를 조회합니다.

- **포인트 이력 조회**
    - `GET /point/{id}/histories`  
      사용자의 포인트 거래 이력을 조회합니다.

- **포인트 충전**
    - `PATCH /point/{id}/charge`  
      사용자의 포인트를 지정한 금액만큼 충전합니다.  
      0 이하 금액 충전 시 예외 발생

- **포인트 사용**
    - `PATCH /point/{id}/use`  
      사용자의 포인트를 지정한 금액만큼 차감합니다.  
      0 이하 금액 또는 보유 포인트 부족 시 예외 발생

---

## 동시성 제어

- userId별 Lock을 활용하여 한 사용자의 포인트에 대한 동시 요청을 제어합니다.
- 저장소(UserPointTable, PointHistoryTable)는 정합성을 보장하지 않고 과제 조건상 수정도 할 수 없으므로, 서비스 계층에서 동시성 제어를 진행했습니다.
- userId별 Lock 메커니즘을 통해 여러 사용자의 동시 요청은 각자 독립적으로 처리됨을 보장합니다.

## 테스트 코드 구조

### 1. 단위 테스트

- **PointServiceUnitTest**
    - 포인트 조회, 충전, 사용 기능 및 예외 케이스(음수, 부족 등) 검증
    - Mock 객체를 활용하여 서비스 로직의 동작만 분리 검증

### 2. 통합 테스트

- **PointIntegrationTest**
    - 실제 인메모리 Table 객체를 사용하여 API 단위로 검증
    - 포인트 조회, 이력 조회, 충전, 사용 등 주요 API의 end-to-end 동작 확인

### 3. 동시성 테스트

- **PointConcurrencyTest**
    - 여러 스레드가 동시에 동일 사용자(또는 여러 사용자)에 대해 충전/사용 요청을 보낼 때 데이터 정합성 검증

## 테스트 환경

- **실제 DB 미사용**: 인메모리 저장소로만 동작
- **저장소 클래스는 thread-safe하지 않음**  
  서비스 계층에서 userId별 Lock으로 정합성을 최대한 보장
- **throttle(랜덤 sleep)**  
  저장소 접근 시 랜덤 지연이 있어, 동시성 테스트 타임아웃을 충분히 크게 잡아야 함
